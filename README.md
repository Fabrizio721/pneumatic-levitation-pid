# Pneumatic Levitation System with PID Control

Closed-loop pneumatic levitation system developed to regulate the vertical position of a lightweight ball using a PID controller.

The project combines mathematical modelling, control-system analysis, MATLAB simulation, embedded control implementation, mechanical design and experimental validation on a physical prototype.

This project was developed as part of the **Control Engineering I** course at Universidad Peruana de Ciencias Aplicadas (UPC).

---

## Project Overview

The objective of the project was to maintain a polystyrene ball at a desired vertical position inside a tube using the airflow generated by a DC fan.

An **HC-SR04 ultrasonic sensor** continuously measures the position of the ball.

The measured position is compared with a desired reference or setpoint. The resulting error is processed by a PID controller implemented on an **Arduino Nano**.

The controller regulates the fan power through a PWM signal applied through an **L298N motor driver**.

The system works as a closed-loop control system and continuously adjusts the actuator output to compensate for disturbances and position variations.

## Mathematical Modelling

The pneumatic plant was approximated using a mathematical model based on the vertical motion of the levitated ball.

Newton's second law was used as the basis of the model.

Around an operating point, the system was represented using an equivalent second-order model.

The mathematical model was used to:

- Analyze the dynamic behaviour of the plant
- Obtain an approximate transfer function
- Study system stability
- Design the PID controller
- Perform MATLAB simulations
- Compare different control strategies

The real pneumatic plant presents nonlinearities, therefore the mathematical model represents an approximation of its behaviour.

## PID Controller Design

A PID controller was designed to improve the dynamic behaviour of the pneumatic levitation system.

The main control objectives were:

- Improve system stability
- Reduce oscillations
- Improve reference tracking
- Reduce steady-state error
- Improve damping
- Compensate for disturbances

The controller combines three actions:

- **Proportional action:** reacts to the current control error.
- **Integral action:** reduces accumulated and steady-state error.
- **Derivative action:** reacts to changes in the error and improves damping.

The controller was initially designed theoretically and analyzed using MATLAB before being implemented on the physical system.

## P, PI and PID Comparison

Different control strategies were compared during the design process.

The main observed behaviours were:

| Controller | Behaviour |
|---|---|
| P | Fast response but presents error and oscillations |
| PI | Reduces permanent error but may increase oscillations |
| PID | Improves stability, precision and damping |

The PID controller provided the best overall balance between response speed, stability and error reduction.

![P, PI and PID comparison](images/controller_comparison.png)

## Embedded Control Implementation

The PID algorithm was implemented on an **Arduino Nano**.

The embedded control loop performs the following operations:

1. Read the setpoint potentiometer
2. Read the Kp, Ki and Kd potentiometers
3. Measure the distance using the HC-SR04 sensor
4. Calculate the vertical position of the ball
5. Calculate the error between the setpoint and measured position
6. Calculate the PID control action
7. Limit the controller output
8. Generate the PWM signal
9. Apply the PWM signal to the fan through the L298N
10. Display system information on the LCD
11. Send operating data to the Serial Plotter
12. Repeat the control loop continuously

![PID control flowchart](images/control_flowchart.png)

The control implementation also considers PWM output limitations to prevent commands outside the actuator operating range.

## Experimental PID Tuning

After implementing the controller on the real prototype, the PID parameters required additional experimental adjustment.

This was necessary because the physical system presented effects that were not fully represented by the simplified mathematical model.

The main differences between the model and the real plant included:

- Nonlinear airflow
- Turbulence inside the tube
- Ultrasonic sensor noise
- Lateral movement of the ball
- Fan limitations
- PWM saturation
- Variations in the real pneumatic plant

The PID parameters were therefore adjusted experimentally until a stable response was obtained.

This stage demonstrated the difference between theoretical controller design and real-world implementation.

## Experimental Validation

The controller was validated using the physical pneumatic levitation system.

During the experimental test reported in the project, a reference of approximately **23.64 cm** was established.

During the stable operating interval, the measured ball position remained approximately between:

- **23.56 cm**
- **23.66 cm**

Despite the presence of turbulence, sensor measurement variations and movement of the ball, the controller was able to maintain the system close to the desired reference.

## PWM Behaviour

The PWM command continuously changed to compensate for variations in ball position.

During the stable operating regime, the PWM output remained mainly between:

**240 and 245**

and occasionally reached the maximum value of:

**255**

when larger position deviations occurred.

This behaviour demonstrated that the controller continuously modified the fan power in order to recover the desired ball position after disturbances.

---

## Main Engineering Challenges

### Nonlinear Pneumatic Behaviour

The airflow produced by the fan does not behave as an ideal linear actuator.

This generated differences between the mathematical model and the real prototype.

### Turbulence

The movement of air inside the vertical tube produced disturbances that affected the position of the ball.

### Ultrasonic Sensor Noise

The HC-SR04 measurements presented small variations caused by sound reflections and ball movement.

### Actuator Saturation

The system required relatively high PWM values during operation and occasionally reached the maximum PWM output.

### Model-to-Hardware Transition

The theoretical controller provided a starting point, but experimental tuning was required to achieve stable behaviour on the physical system.
